# WhatsApp Translator

**Собственный веб-клиент WhatsApp с автоматическим переводом.** Один WhatsApp-номер, несколько личных переписок, работа с Windows 11 и Android через браузер. Входящие сообщения показываются на русском, ответы пишутся по-русски и отправляются собеседникам после перевода на настроенный язык.

**Статус:** ранняя рабочая версия (MVP). Автоматические проверки кода не заменяют тестирования с реальным WhatsApp-аккаунтом и на конкретном VPS. Подключение выполняется через неофициальную библиотеку Baileys — существует риск ограничения или блокировки номера.

## Установка на Ubuntu 24.04 — одна команда

**Основной и рекомендуемый способ установки** — один интерактивный скрипт, который сам скачивает проект, проверяет сервер, подбирает параметры и запускает установку только после твоего подтверждения.

~~~bash
curl -fsSL https://raw.githubusercontent.com/Alex66166/Whatsapp-translator/main/bootstrap.sh -o /tmp/wa-bootstrap.sh && sudo bash /tmp/wa-bootstrap.sh
~~~

Перед запуском:

- Репозиторий должен быть **Public**, иначе скачивание с GitHub без авторизации не работает.
- Нужны Ubuntu Server **24.04**, права `sudo`, интерактивная SSH-консоль и стандартные утилиты `curl`, `tar`, `ss`.
- Для рекомендуемого размещения достаточно VPS с **2 ГБ RAM и 4 ГБ SWAP** при небольшой нагрузке; локальная ИИ-модель не устанавливается.
- Подготовь бесплатный ключ [Groq API](https://console.groq.com/keys), пароль для будущего веб-интерфейса и доменное имя. Для автоматической выдачи сертификата требуется DNS-запись домена на VPS и доступ к TCP 80. Веб-клиент может слушать **внешний HTTPS-порт на выбор**: 443 или другой разрешённый порт (его нужно открыть в файрволе).
- Загружаемый скрипт выполняется от root. Прежде чем запускать его на важном сервере, можно [прочитать исходник bootstrap.sh](bootstrap.sh).

### Что происходит после запуска

1. **Загрузка.** Скрипт скачивает текущую ветку `main` с GitHub во временную папку и проверяет основные файлы.
2. **Аудит (только чтение).** Анализируются ОС, RAM, SWAP, диски, установленные приложения, процессы, службы systemd, TCP/UDP-порты, сетевые интерфейсы, Nginx/Apache/Caddy, контейнеры, виртуальные хосты, файрвол, Fail2ban и сертификаты. Пакеты и настройки на этом этапе не изменяются.
3. **Результат аудита.** Краткие сведения отображаются в консоли; полный отчёт автоматически сохраняется в `/root/whatsapp-translator-audits/`. **Предложения открыть или подтвердить отчёт нет.** В отчёте могут содержаться IP-адреса и сетевые настройки: **не выкладывай его публично**.
4. **Рекомендации.** Скрипт предлагает каталог приложения, имя службы и пользователя, свободный внутренний порт Node.js, внешний HTTPS-порт (по умолчанию 443) и безопасный способ подключения к существующему веб-серверу.
5. **Настройка.** Для предлагаемого параметра нажми **Enter**, чтобы принять значение, либо введи собственное. Домен запрашивается отдельно. **Пароль веб-интерфейса — от 6 символов, без требований к сложности, ввод скрыт.** **Ключ Groq вводится видимым текстом:** его можно вставить из буфера обмена терминала (обычно Ctrl+Shift+V), сразу увидеть вставленное значение и исправить при необходимости. Ключ не записывается в отчёт аудита.
6. **Подтверждение установки.** После автоматического аудита **не требуется вводить `AUDIT-APPROVED`**. Установщик показывает план изменений. **До ввода слова `INSTALL` ничего не устанавливается и не перенастраивается.** Отказ на любом этапе останавливает процедуру.
7. **Развёртывание.** Создаются служба systemd, настройки приложения и база; при согласованном автоматическом режиме Nginx оформляется HTTPS. При обновлении существующего приложения предварительно создаётся зашифрованная резервная копия.
8. **Проверка.** После установки выполняется проверка запущенного локального HTTP API, ресурсов и пробный запрос перевода в Groq. При неудаче теста появится предупреждение, но работающий сервис не удаляется.

**Важное ограничение:** автоматические рекомендации основаны на проверках, но не гарантируют обнаружения всех конфликтов. Если аудит показал сложную конфигурацию VPS, лучше выбрать безопасный ручной режим веб-сервера и отдельно проверить отчёт.

### Параметры, которые предлагает мастер

| Параметр | Поведение |
|---|---|
| Каталог программы, имя службы, пользователь Linux | Предлагаются, разрешено изменить |
| Внутренний порт Node.js | Слушает только `127.0.0.1` и не доступен напрямую из интернета |
| Внешний порт HTTPS | Запрашивается отдельно; по умолчанию `443`, возможен другой, **не совпадающий с внутренним** |
| Способ подключения веб-сервера | `manual`, `nginx` либо подключение к существующему Nginx/Apache/Caddy; рекомендация по результатам аудита |
| Домен для HTTPS | Обязательно вводится |
| Email для Let's Encrypt и каталог ACME | Запрашиваются при выборе `nginx` |
| Пароль веб-клиента | От 6 символов, без требований к сложности; ввод скрыт при первой установке |
| Groq API-ключ | Вставка из буфера обмена, **видимый ввод** при первой установке; не показывай ввод на трансляции экрана |
| Модель Groq и язык собеседников по умолчанию | Предлагаются значения, разрешено изменить |
| Размер одного фото и общая квота сообщений + фото | По умолчанию 8 и 512 МБ. При переполнении работает FIFO по старейшим завершённым сообщениям |
| Каталог шифрованных резервных копий | Запрашивается при обновлении/переустановке |

Все пользовательские параметры конкретной установки хранятся **на VPS**; номера телефонов и контакты в исходниках не прописаны.

### Если на VPS уже работает веб-сервер с TLS

Установщик теперь умеет **подключить переводчик через существующий веб-сервер**, не создавая вторую службу Nginx и не меняя старые сайты без согласия. Мастер оценивает работающие службы и предлагает режим в соответствии с найденным сервером:

| Что обнаружено | Рекомендуемый режим и действие |
|---|---|
| Работает Nginx с HTTPS | `nginx-existing`: отдельный `server` на выбранном HTTPS-порту, существующий подходящий сертификат |
| Работает Apache с HTTPS | `apache-existing`: отдельный `VirtualHost` на 443, существующий подходящий сертификат |
| Работает Caddy | `caddy-existing`: отдельный блок сайта в `/etc/caddy/Caddyfile`, HTTPS обслуживает сам Caddy |
| Веб-сервер не найден, порты свободны | `nginx`: установка Nginx и выпуск отдельного сертификата Let's Encrypt |
| Несколько веб-серверов, нестандартная конфигурация, неизвестный процесс на 80/443 | `manual`: запускается только локальный сервер и создаётся образец конфигурации |

**Как работает автоматическая интеграция с TLS:**

1. Ты вводишь домен переводчика, например `chat.example.com`.
2. Для Nginx и Apache программа ищет действующий сертификат в стандартных каталогах Let's Encrypt и проверяет **соответствие имени домена, срок действия, совпадение сертификата с закрытым ключом**. Если сертификат из другого каталога — можно указать пути вручную.
3. Если проверка не пройдена, существующий веб-сервер **не перенастраивается**. Выбери подходящий домен/сертификат либо отдельно выпусти новый. Сертификат `example.com` не обязан подходить для `chat.example.com`; wildcard `*.example.com` обычно подходит.
4. Перед подключением проверяется конфликт доменного имени, после чего установщик требует подтверждение `INTEGRATE`. Для Nginx и Apache создаётся отдельный сайт без перезаписи других конфигураций.
5. Проверяется синтаксис веб-сервера, выполняется `reload`; если проверка или перезагрузка не прошла — новая конфигурация откатывается. Резервные копии изменяемых файлов хранятся в `/root/whatsapp-translator-config-backups/`.

**В случае Caddy** применяется штатное автоматическое управление HTTPS: при необходимости он сам запросит сертификат для нового домена. Это не гарантирует переиспользование уже выданного сертификата. Для автоматического выпуска нужны корректный DNS и доступность портов снаружи.

Автоматическая интеграция в данном MVP поддерживает **стандартные конфигурации Ubuntu**: каталоги сайтов Nginx/Apache или основной `/etc/caddy/Caddyfile`. При нестандартном устройстве сервера используется `manual`, чтобы не сломать существующие сайты. После успешной интеграции нужно проверить адрес через внешний браузер и убедиться, что HTTPS работает.

## Как пользоваться после установки

1. Открой адрес сайта **по HTTPS** с Windows или Android (если внешний порт не 443, добавь его после двоеточия: `https://домен:8443`) и введи пароль, заданный при установке.
2. На смартфоне открой обычный WhatsApp → **Связанные устройства** → **Привязка устройства** и отсканируй QR-код, который появится в веб-клиенте.
3. Слева показываются **до 20 контактов последних личных чатов**, отсортированных по времени активности WhatsApp. Для **новых контактов галочка «Перевод» включена по умолчанию**; её можно выключить отдельно для любого чата. Старая переписка не загружается в интерфейс.
4. Читай перевод входящих сообщений на русском. Рядом можно увидеть исходный текст; полученные фотографии отображаются в переписке, а их подписи переводятся.
5. Пиши текст в поле ввода. Если галочка **«Перевод» включена**, текст переводится с русского на выбранный язык перед отправкой; если **выключена**, обычное сообщение отправляется **без изменений и без обращения к Groq**. **Enter** отправляет, **Shift+Enter** добавляет перевод строки.
6. При желании добавь сайт на главный экран Android либо установи его как веб-приложение через Chrome/Edge на Windows.

**Один QR-код привязывает весь WhatsApp-аккаунт**, а не отдельный контакт. Чаты загружаются динамически, перевод каждого включается отдельно. При работе в обычном приложении WhatsApp сообщения не подменяются переводом автоматически.

### Сброс сохранённых контактов и повторное получение метаданных

Если ранее имена или список контактов синхронизировались неправильно, можно однократно **сбросить контактный кэш** во время обновления, сохранив привязку WhatsApp, сообщения, фотографии, токены и выбранные языки:

~~~bash
curl -fsSL https://raw.githubusercontent.com/Alex66166/Whatsapp-translator/main/upgrade.sh -o /tmp/wa-upgrade.sh && sudo bash /tmp/wa-upgrade.sh --reset-contacts
~~~

Во время обновления оставь прежний внешний HTTPS-порт, нажав Enter. Опция `--reset-contacts` очищает локальную импортированную адресную книгу, сохранённые имена и отметки активности. Ненужные строки чатов удаляются, а строки, на которые ссылаются сохранённые сообщения, остаются без имён и с нулевой активностью. После сброса **в левой панели не останется старых контактов**; перевод включится по умолчанию для всех очищенных и вновь появляющихся записей. Если пользователь вручную выключит перевод для какого-либо контакта, настройка далее сохраняется.

**Важно:** сброс не запрашивает у WhatsApp новую полную синхронизацию принудительно. Приложение сможет заново построить список лишь из метаданных, которые WhatsApp реально отправит после перезапуска и из последующих сообщений. Для давно связанного устройства они могут не прийти без новой QR-привязки; повторная привязка также **не гарантирует** получение всех последних 20 собеседников. Сбрасывать или удалять каталог `.data/auth` вручную не нужно.

### 20 последних контактов без загрузки переписок

Левая панель показывает **максимум 20 собеседников из последних личных чатов WhatsApp**, а не всю телефонную книгу. Список формируется из метаданных разговоров: идентификатора собеседника, доступного имени и времени последней активности. Группы не включаются. Поиск фильтрует только эти 20 записей.

Приложение использует **только метаданные исторических сообщений** (собеседник, время, доступное имя), когда WhatsApp их передаёт. Тексты, фотографии и вложения старых переписок не сохраняются и не переводятся. Данные `chats[]` дополняются этими метаданными, потому что на некоторых аккаунтах WhatsApp возвращает метаданные сообщений, но не список чатов. После подключения новые сообщения сохраняются даже у контактов **с выключенным переводом** — они показываются в оригинале. При включённом переводе новые входящие переводятся на русский.

**Техническое ограничение:** WhatsApp/Baileys может передать служебные метаданные чатов вместе с начальной синхронизацией истории. Уже связанное устройство не всегда получает событие синхронизации повторно после обновления кода; поэтому при уже привязанном WhatsApp список может временно остаться неполным. В крайнем случае для получения новых первоначальных метаданных понадобится **добровольная новая привязка** устройства по QR, но она также не гарантирует все 20 контактов. На уровне протокола нельзя гарантировать получение ровно 20 последних собеседников без передачи каких-либо зашифрованных исторических данных. Приложение игнорирует их содержимое и не скачивает старые фотографии, а полный режим `WHATSAPP_FULL_SYNC=1` по умолчанию выключен. Если WhatsApp передал сведения лишь о двух недавних чатах, на экране будут только две записи: недостающие контакты приложение не придумывает.

**Ни импорт всей адресной книги `.vcf`, ни ручной поиск по любому номеру в этом интерфейсе не используются.** Сохранённые на смартфоне имена WhatsApp может не передать: иногда доступно только однобуквенное имя профиля вроде `A`. Для таких контактов показывается короткая подсказка `LID` (это не номер телефона). Старые импортированные данные в базе не удаляются — они просто не показываются как недавние чаты.

Для обновления уже установленного VPS с сохранением WhatsApp-сессии, настроек, порта и TLS:

~~~bash
curl -fsSL https://raw.githubusercontent.com/Alex66166/Whatsapp-translator/main/upgrade.sh -o /tmp/wa-upgrade.sh && sudo bash /tmp/wa-upgrade.sh
~~~

Скрипт уточнит внешний HTTPS-порт. Для сохранения нынешнего значения нажми Enter. После успешного обновления обнови страницу браузера **Ctrl+F5**. Старые сессии WhatsApp повторно привязывать не требуется.


### Что реализовано и чего пока нет

- Поддерживаются личные текстовые чаты, автоматический перевод по выбранным контактам и обычные сообщения без перевода. Первый входящий текст нового контакта сохраняется и показывается, даже если перевод изначально выключен.
- Входящие фотографии из выбранных чатов сохраняются на VPS, показываются авторизованному пользователю; подписи переводятся. Размер отдельного изображения и общий объём ограничиваются настройками.
- Не реализованы отправка фотографий из веб-клиента, перевод голосовых сообщений, групповые чаты, нативные push-уведомления и импорт всей старой переписки. Одноразовые изображения не сохраняются.
- Незавершённые **входящие переводы хранятся в SQLite** и продолжаются после перезапуска сервиса. Незавершённые **исходящие отправки не повторяются автоматически**, поскольку WhatsApp мог принять сообщение до обрыва соединения.
- Отправки через веб-интерфейс связываются с идентификаторами WhatsApp для исключения обычных дублей в истории. При сетевом сбое **перед повторной отправкой проверь обычный WhatsApp**, чтобы не отправить сообщение ещё раз.
- После явного выхода связанного WhatsApp-устройства появится действие **«Привязать WhatsApp заново»** с подтверждением паролем. Старые ключи перемещаются в защищённый локальный каталог, а новая сессия подключается по QR.
- При ошибке Groq приложение не должно намеренно отправлять исходный русский текст.
- Доступность истории, контактов и изображений зависит от фактической синхронизации через Baileys.

## Резервное копирование, обновление и переустановка

Приложение хранит конфигурацию в `.env`, а авторизацию WhatsApp, базу сообщений и фотографии — в `.data/` внутри выбранного каталога установки. Эти каталоги **не включаются в GitHub**.

### Резервная копия

Запусти скрипт из каталога установленной программы (в примере показан предлагаемый по умолчанию путь; если выбрал другой, замени его):

~~~bash
sudo bash /opt/whatsapp-translator/backup.sh
~~~

Укажи каталог установки, **отдельный каталог для копий**, имя службы systemd и пароль шифрования. Для согласованного сохранения SQLite скрипт на время остановит указанную службу и затем запустит её снова. Будут сохранены настройки, сессия WhatsApp, база данных и изображения. Результат — зашифрованный архив `*.tar.gz.enc`.

**Обязательно скопируй архив за пределы VPS**: резервная копия только на том же сервере не защитит от потери сервера. Пароль архива нельзя восстановить.

### Обновление поверх установленной версии

Запусти **ту же единую команду установки** из раздела выше. Мастер повторно проведёт аудит и предложит параметры. Для сохранения данных выбери **тот же каталог приложения и локальный порт**, что и в существующей установке. Перед заменой кода установщик запросит каталог бэкапов, создаст зашифрованный архив и только затем продолжит обновление. `.env` и `.data/` сохраняются.

Не меняй режим reverse-proxy без проверки действующей HTTPS-конфигурации. Скрипт не обновляет пароли или Groq-ключ при обычной переустановке — используются ранее сохранённые значения.

### Чистая переустановка ОС или перенос на новый VPS

1. На старом сервере создай зашифрованную резервную копию и перенеси её в безопасное место за пределами VPS.
2. На новой Ubuntu 24.04 выполни **основную команду установки**, согласуй новые параметры и HTTPS.
3. Скопируй архив на новый сервер и запусти восстановление (укажи фактический путь установки):

~~~bash
sudo bash /opt/whatsapp-translator/restore.sh
~~~

4. Введи путь к приложению, имя службы, путь к архиву, пароль и подтверждение `RESTORE`. Текущие `.env` и `.data/` будут **заменены** данными из архива, затем служба запустится. Сначала сделай отдельный бэкап текущего состояния, если там есть нужные данные.

Конфигурация веб-сервера, системные пакеты и файл systemd-службы **не входят** в архив — создаются по итогам новой установки. Если WhatsApp сбросил связанное устройство, потребуется вновь отсканировать QR-код.

## Управление и диагностика

Имя службы выбирается во время установки. Если оставлено предлагаемое значение, команды такие:

~~~bash
sudo systemctl status whatsapp-translator
sudo journalctl -u whatsapp-translator -n 100 --no-pager
sudo systemctl restart whatsapp-translator
~~~

Для проверки ресурсов VPS, локального API и действительного Groq API используй команду из **фактического каталога приложения** (при стандартном пути):

~~~bash
cd /opt/whatsapp-translator && sudo -u wttranslator npm run doctor
~~~

Диагностика использует один реальный запрос к Groq и поэтому расходует часть бесплатной квоты.

Аудит без установки можно запустить отдельно из установленного каталога:

~~~bash
sudo bash /opt/whatsapp-translator/audit.sh
~~~

Для отдельной проверки исходников: `npm install`, `npm run check`, `npm test`. Результаты автоматических проверок смотри в [GitHub Actions](https://github.com/Alex66166/Whatsapp-translator/actions).

## Безопасность и ограничения

- Baileys использует **неофициальное** подключение WhatsApp Web. Есть риск ограничения или блокировки WhatsApp-аккаунта.
- Текст из чатов, где включён перевод, передаётся во внешний Groq API; проверь условия хранения/обработки данных сервиса, прежде чем переводить конфиденциальную переписку.
- У Groq есть бесплатный тариф, но лимиты, доступность моделей и условия могут меняться. Отдельный ключ API нужен даже при подписке ChatGPT.
- Сессия WhatsApp, содержимое базы и ключи API чувствительны: их нельзя публиковать, коммитить или передавать вместе с отчётом сервера.
- Доступ к веб-клиенту должен быть через **HTTPS**. Не открывай внутренний Node.js-порт в интернет напрямую.
- Проверки GitHub Actions включают SQLite, перевод по имитации Groq API, повторную привязку сессии, логику браузерного чата, **зашифрованный бэкап и восстановление**, а также имитацию подключения HTTPS через Nginx с откатом.
- При сбое развёртывания установщик восстанавливает предыдущие файлы приложения, systemd-службу и собственный Nginx vhost. **Уже установленные/обновлённые системные пакеты автоматически не откатываются.** Для полноты восстановления VPS рекомендуется иметь отдельный снапшот хостинга.
- Текущая версия **не прошла полноценное испытание реального подключения WhatsApp, фото и интеграции со всеми вариантами веб-серверов на твоём VPS**. Для первой проверки лучше использовать неосновной аккаунт.
